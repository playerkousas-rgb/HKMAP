# 瘦身系統 · 防增肥守則（HKMAP）

> 目的：防止 Vercel 儲存配額爆滿，同時**功能／UI／體驗 100% 零倒退**。
> 原則：人會忘記，機器不會 —— 所有規範都落在零依賴守門腳本 `scripts/slim-guard.mjs`，
> 違反即 `exit 1`（本機 `npm run check:slim`、PR 時 GitHub Actions 都跑同一份）。
> 改規範＝改「四件套」＋喺本文件 §8 落紀錄，唔准順手改常數過 check。
>
> 呢套係 2026 Scout System 全家標準，對齊 `AYP/scripts/check.js`（防增肥預算）
> 與 `drawtheroute/scripts/slim-guard.mjs`（守門腳本格式）。

## 1. 邊part係「瘦身系統」

| 檔案 | 角色 |
|---|---|
| `.vercelignore` | Vercel 上傳黑名單：只上線真正用得到嘅嘢（本倉冇 build 步，根目錄即產物） |
| `scripts/slim-guard.mjs` | 守門腳本（純 Node、零依賴、唔准裝套件）：8 組規則＋體積儀表板 |
| `package.json` | 入口：`npm run check:slim`（`dependencies` 同 `devDependencies` **永遠為零**） |
| `.gitignore` | 入倉黑名單：備份／暫存／日誌／`uploads/`／`package-lock.json` |
| 本文件 | 預算點名表＋流程＋changelog（規則嘅「人睇版本」） |

## 2. 常用命令

```bash
npm run check:slim          # 守門（全綠先好部署）
node scripts/slim-guard.mjs # 同上，唔經 npm
python3 -m http.server 8080 --bind 0.0.0.0   # 本機預覽（npm start）
```

## 4. 守門規則逐條（違反即紅）

1. **必備檔案**：4 個 HTML、`css/app.css`、`js/app.js`、`js/report.js`、`js/offline.js`、`sw.js`（離線底圖，必須在根目錄 scope 才覆蓋全站）、`assets/mark.svg`、`vercel.json`、`.vercelignore`、守門腳本、本文件——一個都不能「順手刪」。
2. **`.vercelignore` 黑名單齊唔齊**：`node_modules`、`dist`、`coverage`、`docs`、`scripts`、`*.log`、`*.bak/tmp/old/orig/map`、`.DS_Store`、`Thumbs.db`、`uploads/`。
3. **死重掃描**：倉庫內唔准有備份／暫存／日誌檔；唔准有 `uploads/`（會隨使用量累積儲存空間）；已廢棄檔案（`MD`、`index.legacy.html`、`js/app.legacy.js`）唔准復活。
4. **體積預算**：見 §3。
5. **部署包雙向核對（本倉最有用嘅一条）**：
   - HTML／CSS／JS 引用咗嘅本機檔案 → **必須存在**（防死 link）＋ **必須喺部署包內**（防 `.vercelignore` 誤殺，例如 `教學.md` 俾 `mock.html` 引用，入黑名單即線上 404）；
   - 喺部署包內但**冇人引用**嘅 `css/ js/ assets/` 檔案＝死重 → 直接紅（杜絕「放低張圖忘記刪」）。
   - 唯一例外：`print.html`（舊書籤／舊連結回落 stub，冇人 link 係正常）。
6. **回報系統接入完整**：見 §6，缺任何一项即紅（包括「列印時要收埋 widget」）。
7. **Git 追蹤範圍**：`node_modules/`、`dist/`、`.vercel/` 唔准入倉；每次跑都會列出「Git 追蹤總量 vs 部署包」，即瘦身儀表板。
8. **根目錄雜檔提示**：新加喺根目錄嘅檔會被問一句「上線用唔用到？」。

## 5. 新增檔案／資產＝三連動

1. 喺 HTML（或 JS/CSS）**真正引用**佢——冇引用就唔好擺。
2. 屬「上線用唔到」嘅（文件、腳本、示範素材）→ 放 `docs/`、`scripts/` 或加進 `.vercelignore`。
3. 跑一次 `npm run check:slim` 睇綠燈。

圖片規範（同全家一致）：`assets/` 只放**被引用**嘅圖；位圖優先 AVIF／WebP，PNG 靠去中繼＋調色盤壓瘦；高解析設計母檔**唔入倉**（git history 先係備份）。

## 6. 統一回報系統（Scout Admin · 統一回報格式 v1）

- **一行接入**（`index.html` 末尾，全家一樣，只改 `data-app`）：
  ```html
  <script src="https://scout-admin-blue.vercel.app/widget.js" data-app="定向地圖"></script>
  <script type="module" src="js/report.js"></script>
  ```
  資料直接送去區會 Apps Script 接收端：**唔經本站後端、唔使 API key、可以匿名**；後台同 Sheet 欄位全家共用，新系統上線後台唔使改。
- **入口**：頂欄「🐛 回報」按钮（`data-report-open`）。widget 自帶嘅右下角 FAB 喺 `css/app.css` 用 `#scoutw-fab{display:none}` 收起——呢度右下角係地政總署版權聲明 `.credit`，唔畀瞓住。
- **回落**：`js/report.js` 等 widget 載入（每 150 ms 試一次，約 5 秒）；等唔到（離線／被擋）就開獨立回報頁 `https://scout-admin-blue.vercel.app/report.html?app=定向地圖`；連 `<script>` tag 都冇咗就主動補插一次。
- **輕量頁**（`download.html`、`mock.html`）：唔掛完整 widget，只放獨立回報頁連結——零 JS、零體重，同 §5「冇引用就唔好擺」一致。
- **列印**：`@media print` 收埋 `#scoutw-root`，回報 modal 唔會印落紙圖（呢条有守門檢查）。
- `data-app` 未喺 scout-admin `SOURCE_APPS` 登記？照送照收（後台顯示原樣名稱）。要喺後台歸類，去 `scout-admin` 倉加 alias，**本倉唔使改**。

## 7. 零倒退紅線

- 唔准為咗過 check 而調高 §3 預算、删走 §4 規則、或移除 HTML 對檔案嘅引用。
- 唔准引入 build／打包工具（`dependencies` 永遠為零；`vercel.json` 已 `framework: null`，部署＝上傳靜態檔）。
- 改動部署設定（`vercel.json`）前先諗清楚：本倉冇 `buildCommand`，所以守門放喺 `npm run check:slim` ＋ GitHub Actions（`.github/workflows/slim-check.yml`），唔使 Vercel 幫睇。
